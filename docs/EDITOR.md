# Rig Motion Lab 0.2 · 骨骼、动作与部件层级编辑

本更新仍是本地二维实验，不引入 AI 或 Spine 依赖。标准双足骨架的 18 个语义关节和拓扑保持固定；不是任意增删骨骼、重挂父级、网格蒙皮或完整动画软件。

## 更新与旧工程

拉取 main 后重启 Python 后端，浏览器强制刷新。页面顶部显示 **EDITOR 02**。旧 v1 工程会为新字段补默认值；当前动作仍是 `motion`，其它动作保存于 `motion_library`。新工程包保存新增编辑字段，旧 0.1 程序不能读取这些字段，请不要用旧版覆盖新包。

API 地址和 Key 仍不在页面输入。本版没有图片生成请求；`.env` 只用于原有数据目录和可选视频模型设置。

## 骨骼编辑：修改初始结构

在「骨骼编辑」选中左侧树中的关节，或直接拖动画布关节。数值输入 X/Y 可以精确定位；**联动后代**开启时，移动肩会平移同侧肘和腕，移动骨盆会移动全部后代。关闭联动时只修改当前点，连向子节点的骨长因此可能变化。

「骨骼结构编辑」选择骨骼，输入骨长和世界角度；也可以把画布模式切换为「旋转选中骨骼」，拖动该骨骼末端。联动开启时，后代一起旋转/移动，后代骨长不变。骨长单位是固定标定高度，角度为 X 向右、Y 向上的世界角度。方向键微移当前关节，Shift 加大步长；输入框内不截获方向键。

修改武器长度会改变固定绑定使用的长度。任何结构修改都会撤销骨架确认，导出前需要再次点击「确认骨架结构」。骨架结构修改对全部动作生效，若只想修改某个时间点请使用下述动作轨道。

## 动作编辑：只改变特定动作的轨迹

待机、行走、斩击、跳跃与参考动作分别保存参数、控制关键帧和层级轨道。切换动作不再把上一动作的校正点套到另一个动作。每类动作当前只有一套编辑状态，尚无同类型多剪辑库。

暂停并拖到某一帧，打开 **画布调姿 / 松开写入关键帧**：

- **IK 手脚目标**：拖动手腕、脚踝或骨盆，松开后保存并重新求解。拖动期间的橙色把手只是目标指示，完整姿态在松开后更新。
- **FK 骨骼角度**：在骨架上选中一根骨骼并拖动旋转，写入其相对于模板姿态的角度校正。后代跟随、骨长保持。手部转动会带动固定握持的武器。

右侧「关键帧编辑」支持手动输入时间百分比、位置偏移或角度。可以选择已有关键帧后修改其时间/数值，复制到当前采样帧，或者删除。时间轴菱形可点击选中、拖动移时；同一轨道同一时间不允许产生两个点，移入已占用时间会报错而不丢掉原点。

插值定义为**从该关键帧到下一关键帧**：

- 平滑：零端点速度的 smoothstep 校正；基础动作原有轨道仍独立存在。
- 线性：均匀变化。
- 保持：到下一点前保持旧值，到达下一点时切换。

位置轨道仅接受 ΔX/ΔY；骨骼和武器角度轨道仅接受角度。骨骼角度是模板/重定向之后的局部增量，不是直接输入全局绝对角度。没有首/尾点时，控制校正默认在 0%/100% 回到零。显式写入首尾不同的数值可能破坏循环，需要人工验收。

**FK 在 IK 之后应用，具有明确的人工覆盖优先级。** 旋转腿或躯干可能使脚离开原接触目标。系统重新计算目标误差，并显示警告；不会把这种结果声称为“锁脚成功”，也不会偷偷把你编辑的 FK 角度再改回去。需要保持接触时优先修改脚/骨盆 IK 轨道。

单手斩击可修改「命中时刻」，它同时移动挥击轨道的命中位置和导出 hit 事件；必须晚于蓄力结束至少 3%。事件帧取最接近指定时刻的采样帧。不是所有修改后的动作都会自然或满足碰撞约束。

## 部件层级与绑定

左侧部件列表**从前到后**显示。拖动条目、点击上下箭头，或使用「置于最前/最后」。圆点切换显隐。也可以点击角色预览中有 Alpha 的像素选择对应附件，避免透明大矩形挡住其它部件的选择。

右侧可以改名称、绑定骨骼、连接点、缩放、旋转、偏移。名称变化不改变稳定 ID。绑定骨骼决定跟随谁；层级只决定谁盖住谁，二者互相独立。重新绑定不会自动推断新的握持点，需检查 A/B 和偏移。

层级编辑有两个范围：

**初始层级**：修改全局部件 `z`/`visible`，所有动作共用。相同 z 以原始部件顺序稳定排序。若当前动作已设置遮挡关键帧，该帧会覆盖基准值。

**当前动作/当前时刻**：写入当前动作的 `layer_keys`。可以在起始时间记录全部层级，再到挥击阶段把武器移到身体后面，随后在收招阶段重新记录前景顺序。层级只做保持/阶跃，不做插值；在首个关键帧之前使用初始值，之后保持到下一个点。

层级列表里的记录可以跳转或删除。删除部件时清除该部件在全部动作中的层级引用。导出 PNG、实时预览和 motion.json 使用相同的排序逻辑。循环动作不会导出重复的 100% 帧，所以仅在 100% 写入一个层级切换不会显示在导出序列里；需要把切换放在已采样的时刻。

## 撤销、保存、重开

所有已成功保存的编辑保留最多 24 个当前工程会话快照（最多 23 步撤销），支持工具栏按钮、Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z 或 Ctrl+Y。文本输入框仍使用浏览器文本撤销。撤销/重做也会保存新 revision，不回滚服务器版本号。

刷新页面或切换到另一工程后，不保留会话撤销栈；最终修改保存在本地 project.json 和 `.riglab.zip`。图片文件不删除、不反复重采样，撤销绑定仍可恢复此前的本地图片。并发 revision 冲突会拒绝覆盖并重新载入，不能通过撤销强制覆盖另一窗口的修改。

## 开发与验证

- `lab/editing.py`：结构变换、后代旋转、层级评估。
- `lab/models.py`：新增插值、骨骼角度轨道、命中时间、LayerKey、独立动作库与校验。
- `lab/motion.py`：FK 校正和实际目标误差重算。
- `lab/renderer.py`：相同层级规则用于预览与 PNG 导出。
- `lab/static/editor.js` / `editor.css`：独立编辑模块，挂接主工作台生命周期。
- `POST /api/projects/<pid>/rig/edit`：带 expected_revision 的结构编辑；其它编辑仍使用现有 PUT、solve、export 和工程包接口。

运行 `python -m pytest -q`。本次 **85 项测试通过**（原 51 项 + 新 34 项），**24 项 Chromium 界面桥接检查**通过，另执行 **9 项真实本机 HTTP 检查**。Python 编译及两个 JS 的语法检查通过。

Chromium 在交付环境禁止直接导航 localhost；界面验证使用本地 DOM + Python 真实 HTTP 桥接，未禁用管理策略。这不是原生浏览器网络端到端测试。素材均为内置分层示例，未用用户完整素材进行美术验收，也未运行真实视频模型。

本次验证记录在 `editor-tests.txt`、`editor-browser-results.json`；工程包包含额外界面截图。`VALIDATION.md` 和早期截图仍保留为 v0.1.0 的历史记录。
