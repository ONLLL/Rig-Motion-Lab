# Rig Motion Lab 0.3 · 模板动作编辑与部件选取

本版在原有骨架结构、校正轨道及层级编辑之上，新增**独立的完整姿势关键帧**。
默认仍按原参数模板播放；转换后才直接编辑模板动作本身。没有图片 API 调用。

## 更新和兼容

`git pull --ff-only origin main` 后重启 Python 后端，并强制刷新浏览器。页头应显示 `EDITOR 03`。
旧 0.1/0.2 工程会用新字段默认值读取；用 0.3 保存的工程不要再交给旧版覆盖。
API 地址与 Key 不在页面填写。本版不需要它们，`.env` 仍只用于原有本地配置。

## 1. 把当前模板变成可编辑动作

1. 在「动作实验」选择待机、行走、斩击或跳跃，先调整参数并预览。
2. 点击右侧 **将当前模板转为可编辑关键帧**。程序会捕获当前已求解的完整姿势，包括旧 IK/FK 校正，而不是生成一组全为零的偏移。
3. 时间轴出现一排金色「模板姿势关键帧」。每个菱形是一份完整姿势；可以点击、拖动移时、插入、复制或删除。
4. 默认按当前采样帧数捕获。循环动作额外保留一个 100% 闭合边界，但导出不重复这个末尾帧；非循环动作本来就包含终点。

转换后，参数模板不再执行。步幅、抬脚高度、攻击幅度等原生成参数冻结；时长、输出帧数、根运动显示方式和相机仍可改。改输出帧数只会重新采样已有关键帧，不会重建模板或丢弃编辑。

**返回原参数模板**恢复转换前的参数与旧校正轨道，保留当前遮挡层级。当前页面的撤销可以恢复姿势编辑；关闭页面前请保存工程包，不要把会话撤销当作长期版本管理。各动作分别保存，修改行走不会把同一组姿势套给斩击。

## 2. 直接编辑完整姿势

选定一个金色关键帧，开启「拖动画布直接调姿」。左右画布都可操作：

- **FK · 点击部件后旋转**：在角色图上选中手臂、腿、头或武器后拖动；也可以在骨架上选中骨骼旋转。固定骨长，后代跟随。
- **IK · 拖动手脚目标**：拖动手腕、脚踝，重新计算同侧的两骨链；不可达目标不会拉长骨骼。骨盆目标用于平移整个人，不自动把脚留在原处。
- 移动过程中实时显示本地姿势，**松开后才保存并调用本地求解**。取消指针操作不产生关键帧。
- 右侧目标坐标是预览的固定角色坐标；骨骼角度是父骨骼空间的局部角度，武器角度相对于右前臂。它们不是附加偏移量。

若当前时间不是现有关键帧，应用姿势或「记录当前完整姿势」会插入一个新关键帧。时间输入、关键帧移动可精确到非采样时刻，预览不强行跳到最近输出帧。

插值属于**当前关键帧到下一关键帧**：线性、平滑、保持/阶跃。旋转采用转换时展开的局部角度，避免 ±180° 分界产生意外整圈旋转；需要额外整圈时可明确输入展开角度。

首尾边界不可移动或删除。循环动作的「链接循环首尾姿势」会同步 0%/100% 的骨盆相对偏移和局部角度，不复制整段前进位移或脚的接触编号。其作用只是姿势闭合，不保证速度连续或支撑脚完全静止。

目标时间已有姿势时，移动/复制会拒绝，不覆盖其它点。最多保存 129 个完整姿势。

## 3. 部件列表与角色预览双向联动

- 在左侧列表或右侧下拉框选择部件，角色对应的 **Alpha 轮廓**显示金色描边和轻微着色，不是整个 PNG 外接矩形变色。
- 在角色预览上点击可见像素，选中真正命中的最前部件；列表高亮、属性面板与预览同步，列表会滚动到该部件。
- 大块透明留白不会挡住下面的部件。**Alt + 点击**轮选同一位置实际重叠、可见的部件。鼠标悬停显示浅绿色提示。
- 被完全遮住或当前隐藏的部件可以从列表选择；「透视轮廓」用于找位置。隐藏部件不会参与直接图像点击，也不会因显示透视轮廓而被导出。
- 「高亮选中」和「透视轮廓」可分别关闭。点空白、按 Esc 或点取消选择清空选择。
- 分屏、角色大图和移动端按同一套画布/图片坐标换算拾取。透明度低于 16/255 的像素不参与拾取。

选中状态、悬停、高亮和透视全部属于编辑器叠加层，不修改部件 PNG、工程 revision、骨骼数据或最终导出。部件初始层级和动作层级关键帧仍使用原有保持/阶跃规则。

## 4. 保存与接口

`Motion` 新增：

- `driver`: `template` 或 `keyframes`。
- `pose_keys`: 时间、根偏移、根前进位移、全部局部骨骼角度、相对武器角度、接触与目标诊断数据。
- `source_motion`: 不允许嵌套的转换前模板备份。
- `link_loop_ends`: 编辑器首尾联动开关。

新增本地接口（都受 Host/Origin/`X-Rig-Request: 1` 保护）：

| 请求 | 功能 |
|---|---|
| `POST /api/projects/{pid}/motion/convert` | 捕获当前模板或参考动作，正文包含 `expected_revision` |
| `POST /api/projects/{pid}/motion/restore` | 恢复转换前参数模板，正文包含 `expected_revision` |
| 原 `PUT /api/projects/{pid}` | 保存姿势关键帧、层级等；并发 revision 不匹配时拒绝 |
| 原 `/solve`、`/export` | 统一根据 driver 计算，不在导出时偷偷重跑旧模板 |

保存/重新打开 `.riglab.zip` 会保留完整姿势和模板备份。导出 `motion.json` 也保留该数据；它仍不是 Spine JSON。导入新参考视频/轨迹不会覆盖已编辑的行走；已固化的参考动作需要先恢复参数模板才能替换来源。

## 5. 边界与验收

这是固定双足拓扑上的二维刚性部件编辑，不支持任意新增骨骼、蒙皮网格、碰撞或自动生成更好的动作。直接 FK 插值不会自动锁脚。原始接触目标被保留用于诊断；改变手脚姿势后会报告误差，而不是谎称锁定成功。

转换时原有采样姿势按浮点精度保持；减少关键帧或换采样率后，中间姿势是 FK 插值，不能保证与原程序模板的连续轨迹完全一样。大幅修改骨架比例也需要重新验收动作，不自动重定向全部已制作姿势。

本轮验证：117 项 Python 测试通过；39 项 Chromium 交互检查通过；9 项实际本机 HTTP 检查通过。浏览器检查因环境策略使用 DOM + Python HTTP 桥接，**不是原生浏览器网络端到端测试**。测试包含当前时间直接改姿势、实际画布拖动、时间轴拖动、重叠点击、移动端拾取、撤销、工程重开和真实 PNG 导出。示例角色为程序绘制素材，不是 AI 效果展示；没有调用用户内网服务或真实视频检测模型。

运行：`python -m pytest -q`，启动本机服务后执行 `python tools/editor03_smoke.py`。后者需要开发依赖及 Chromium；常规使用不需要浏览器测试依赖。
